# Telegram Business Archive Mini App

Set `VITE_API_BASE_URL` to the public backend URL, then run:

```sh
npm install
npm run dev
```

For production, use `npm run build` and deploy `dist/` over HTTPS. The backend `FRONTEND_ORIGIN` must exactly match this origin.

## GitHub Pages

Pushes to `main` deploy through GitHub Actions after a separate verification job
passes `npm test`, generator tests, API contract checks and the production build.
Pull requests run verification only. The deploy job publishes the artifact built
by that successful job and receives Pages write permissions only at that stage.
In the GitHub repository, enable **Settings → Pages → Source: GitHub Actions**.
Add a repository variable named `VITE_API_BASE_URL` with the public backend URL
before deploying a working Mini App.

## API contract generation

`src/generated/api.ts` is generated by the pinned `openapi-typescript` development
dependency from `contracts/openapi.json`. `src/types.ts` only aliases generated
models; it does not define independent JSON fields. No generator is shipped to
the browser.

With backend checked out alongside frontend and its Python dependencies installed:

```sh
npm run contracts:sync
npm run contracts:check
```

Sync exports the real backend app schema, updates both repositories' snapshots,
and regenerates TypeScript. Check writes nothing and fails if the live backend,
either snapshot, or generated types disagree. Commit these artifacts together
with the corresponding code changes in each repository.

An isolated frontend checkout builds from its committed snapshot without a Python
installation or backend server. Use `npm run contracts:generate` to regenerate
types from that snapshot and `npm run contracts:test` to test drift detection.
`npm run build` always checks the contract before TypeScript compilation. Backend
CI independently rejects an outdated schema snapshot.

## Optimized archive browsing

Messages show the original followed by every archived edit, with an edit label,
date/time and that version's media. Searches include historical text and captions;
reply previews show the current target. Missing originals, incomplete legacy
history and files with an unknown historical version are labeled explicitly.
Expired media stays in the history as unavailable. Deploy backend migrations
`0006_message_snapshots` and `0007_version_search_indexes` before this frontend.
Older backend responses without `versions` still render a single message.

Chats and older messages load in pages. Photos load near the viewport; documents,
including image documents, load on click. Shared media downloads use an authenticated
32-MiB in-memory cache and release object URLs on unmount or expiry. Cancelled chat
and search requests cannot replace the current view.

Run `npm test` and `npm run build` before deploying through the existing GitHub Pages
workflow. Deploy the backend migrations/API before publishing this frontend: opaque
`next_cursor` values are sent through the `cursor` query parameter.
